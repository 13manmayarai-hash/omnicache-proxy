How Freshness is Guaranteed

AI coding agents fail disastrously when replaying outdated file contents. OmniCache binds every cache entry to cryptographic Git tree deltas and nanosecond modification timestamps.

TARGET FILE CHECK

Nanosecond File mtime Tracking

When an agent requests a file via read_file, OmniCache checks the target file's nanosecond modification timestamp (st_mtime_ns) and file size on local disk. If you edit, save, or reformat code in your editor, the cache key immediately changes and the proxy re-reads fresh disk bytes in real time.

DIRECTORY & GIT DELTA

Git Index & Untracked File Probing

For workspace queries like list_dir or grep_search, OmniCache evaluates directory modification times, untracked working-tree files, and .git/index state. New files, deletions, or staging changes invalidate the directory footprint instantly.

WRITE OPERATIONS

Mutations & Workspace Git Switches

Mutating agent operations (such as write_to_file, replace_file_content, or bash executions) purge affected paths from the SQLite WAL index immediately. Non-git repositories fall back safely to directory and file modification timestamps [TODO: confirm with owner fallback scope].

DATA GOVERNANCE & PRIVACY

Privacy & Data Architecture

OmniCache operates as an air-gapped local sidecar running on 127.0.0.1:8000. Here is a clear breakdown of what traffic the proxy sees, where bytes are persisted, and how data is wiped.

INGRESS PROTOCOL

What the Proxy Sees

Because the sidecar intercepts traffic via ANTHROPIC_BASE_URL, it receives HTTP request payloads including prompt instructions, tool definitions, tool outputs, and forwarded API authorization headers [TODO: confirm with owner exact header capture scope].

STORAGE LOCATION

Where Data is Stored

Tool responses, cryptographic hashes, and telemetry metadata are persisted exclusively to a local SQLite database in WAL mode on your machine (defaulting to ~/.omnicache/cache.db) [TODO: confirm with owner default database file path]. No database contents are synced to any cloud backend.

AIR-GAPPED EGRESS

Network Egress & Zero Telemetry

On cache misses, request headers and bodies are proxied directly upstream to official LLM provider endpoints (e.g. api.anthropic.com) via standard TLS. No repository diffs, code files, or prompt tokens are sent to any third-party telemetry or SaaS analytics [TODO: confirm with owner network telemetry verification].

CACHE LIFECYCLE

How to Clear or Reset the Cache

You can purge all cached entries instantly by running omnicache cache clear or by deleting the local database file ~/.omnicache/cache.db [TODO: confirm with owner CLI clear flag name]. Unsetting the base URL environment variable (unset ANTHROPIC_BASE_URL) completely bypasses the proxy with zero residual proxy state.

FREQUENTLY ASKED QUESTIONS

Frequently Asked Questions

What happens when a file changes on disk while the agent is running?

OmniCache verifies the target file's nanosecond modification timestamp (st_mtime_ns) and byte size. Any file modification causes an instant cache miss, routing the request directly to disk for fresh contents with zero stale hallucinations.

Does OmniCache work completely offline?

Previously cached tool calls replay 100% offline from local SQLite WAL memory. Initial uncached tool executions or model reasoning calls require upstream internet access to contact your LLM provider [TODO: confirm with owner offline replay behavior].

Where are my API credentials stored?

Your ANTHROPIC_API_KEY and provider credentials pass through in-memory to upstream provider endpoints on cache misses and are never written to disk, logged, or cached [TODO: confirm with owner credential security].

How do I bypass or uninstall OmniCache?

To bypass the proxy, simply unset the environment variable (unset ANTHROPIC_BASE_URL) in your terminal session. To uninstall the package completely, run pip uninstall omnicache-proxy.

Which coding agents are supported out of the box?

Claude Code CLI is supported via ANTHROPIC_BASE_URL. Cursor, Windsurf, and custom agent scripts can route traffic by targeting http://127.0.0.1:8000 [TODO: confirm with owner agent configuration matrix].

How is cache storage managed on disk over time?

OmniCache stores entries in a local SQLite database using WAL mode with an LRU (least recently used) pruning policy to prevent unbounded growth [TODO: confirm with owner default cache size cap].
